## 2. Главная страница (`/dashboard`)

### Верх страницы
- **Кнопка онлайн/оффлайн** — большая кнопка с анимацией пульса. Посредник нажимает чтобы стать видимым для покупателей. Статус пингуется на сервер каждые 30 сек.
- **Счётчик слотов** — точки (макс 5), показывает сколько активных заказов занято. Если 5/5 — нельзя брать новые заказы из биржи.

### Три таба (свайп работает)

#### Таб "Мои заказы"
Список всех заказов в работе у посредника — и прямые заявки, и принятые с биржи.

Карточка заказа содержит:
- Фото первого товара (или иконка)
- Номер заказа (ZID или R-XXXX для прямых)
- Первый товар или "имя покупателя · кол-во позиций"
- Статус (цветная метка)
- Сумма заказа

**При нажатии** — снизу выезжает модальное окно с деталями.

#### Таб "Биржа"
Заказы из общего пула, которые ещё никто не взял.

Карточка: фото, ZID, первый товар, кол-во откликов, сумма, ориентировочная комиссия.

**При нажатии** — то же модальное окно с кнопкой "Взять заказ".

#### Таб "История"
Завершённые, отменённые и не найденные заказы. Только для просмотра.

### Модальное окно заказа (выезжает снизу)

Содержит:
- Номер + имя покупателя + дата
- Текущий статус (цветная метка)
- Список товаров с фото, названием, павильоном, количеством и ценой
- Блок: Сумма заказа / Комиссия
- Комментарий покупателя (если есть, у прямых заявок)
- **Кнопки действий** (зависят от текущего статуса):

| Статус заказа | Доступная кнопка |
|---|---|
| `CREATED` (прямая заявка) | "Принять заявку" |
| `ACCEPTED` (прямая заявка) | Информационный текст "Заявка принята — обсудите детали с покупателем" |
| `ASSIGNED` (биржа) | "Начать покупку" |
| `AWAITING_PURCHASE_DATE` (биржа) | "Начать закупку" |
| `PURCHASING` (биржа) | "Передать клиенту" |
| `DELIVERING` (биржа) | Информационный текст "Ожидаем подтверждения клиента" |
| Доступный в бирже | "Взять заказ" (или заблокировано если лимит) |

**Проблема:** из модального окна нет перехода в чат с покупателем.
**Проблема:** для прямых заявок нет кнопок смены статуса после ACCEPTED (нет "Начать закупку" / "Передать" / "Завершить").
**Проблема:** нет кнопки "Отменить заказ".

## 3. Чаты (`/chats`)

### Лейаут
- **Десктоп** — два столбца: список чатов слева (320px), переписка справа
- **Мобайл** — один экран: либо список, либо чат (переключение стрелкой назад)

### Левая панель — список чатов
- Поиск по имени покупателя или номеру заказа
- Фильтр: Все / В работе / Архив
- Кнопка обновления (RefreshCw)
- Карточки чатов:
  - Аватар с буквой + значок "П" для прямых заявок
  - Имя покупателя + время последнего сообщения
  - Превью последнего сообщения
  - Номер заказа, тип (Прямая / Биржа), статус

**Загрузка чатов работает так:** для биржи — перебирает все заказы из `/mediator-orders/my` и для каждого запрашивает `/mediator-orders/:id/chats` (много запросов, медленно). Для прямых — один запрос `/order-requests/chats`.

### Правая панель — переписка

**Шапка чата:**
- Кнопка назад (мобайл)
- Аватар + имя + ZID + тип + текущий статус

**Safety banner (синий, закрывается):**
- "Ведите переговоры только здесь — не переходите в Telegram, WhatsApp"

**Область сообщений:**
- Точечный фон (как в мессенджерах)
- Мои сообщения — справа, фиолетово-индиго градиент
- Сообщения покупателя — слева, полупрозрачный белый
- Системные сообщения — по центру, серый овал
- **Предупреждения об опасном контенте — по центру, красная карточка.** Появляются автоматически сразу после сообщения с:
  - Номером банковской карты (16 цифр)
  - Российским номером телефона (+7/8...)
  - Упоминанием Telegram, WhatsApp, Viber

**Трекер статуса товаров (только для прямых заявок):**
- Расположен между сообщениями и полем ввода
- Заголовок: "Статус товаров" + прогресс-бар + счётчик "X/Y найдено"
- Сворачивается/разворачивается
- Каждый товар: фото, название, павильон, цена × кол-во, текущий статус
- Три кнопки на каждый товар: ✅ Нашёл / ❌ Нет / 🔄 Замену
- Выбранная кнопка выделена рингом
- Если покупатель ответил на запрос замены — кнопки исчезают, показывается результат

**Быстрые ответы (⚡):**
- Панель с 6 заготовленными фразами
- "Добрый день! Приступаю к вашему заказу."
- "Товар найден, скоро отправлю фото."
- "К сожалению, данного товара нет. Предлагаю замену."
- "Заказ выкуплен! Передаю в доставку."
- "Уточните, пожалуйста, размер и цвет."
- "Сейчас нахожусь на рынке, проверяю наличие."

**Поле ввода:**
- Textarea (расширяется до 120px)
- Enter — отправить, Shift+Enter — перенос строки
- Кнопка отправки: фиолетовый градиент когда текст есть, серая когда пусто
- Спиннер при отправке

**Поллинг:** сообщения обновляются каждые 8 секунд пока чат открыт.

### Что НЕ работает в чате
- **Основная проблема:** нет возможности управлять заказом прямо из чата (сменить статус, завершить заказ). Посреднику нужно уходить в Dashboard.
- Нет кнопки "Перейти к заказу" из чата
- Нет подтверждения прочтения сообщения (галочки не реальные)
- Биржевые чаты загружаются медленно (N+1 запрос)
- Нет счётчика непрочитанных сообщений

## 6. Регистрация и верификация

### Поток регистрации
1. `/register` — email + пароль + имя + телефон
2. `/verify` — загрузка документов (паспорт + селфи), настройка комиссии и мин. суммы, аватар
3. Заявка уходит на ручную проверку в `/admin`
4. После одобрения — полный доступ к функционалу

### Статусы верификации
- `NO_PROFILE` — не подавал заявку
- `PENDING` — на проверке (дашборд заблокирован)
- `NEEDS_REVISION` — нужно доработать документы
- `REJECTED` — отклонён
- `APPROVED` — одобрен (полный доступ)
- `FROZEN` — заморожен администратором

## 7. Типы заказов — как они работают

### Прямая заявка (OrderRequest)
**Флоу:**
1. Покупатель выбирает посредника в каталоге → создаёт заявку с товарами из корзины
2. Посредник видит заявку в "Мои заказы" со статусом `CREATED`
3. Посредник нажимает "Принять заявку" → статус `ACCEPTED` → создаётся чат
4. Общение в чате, посредник отмечает статус каждого товара
5. Покупатель видит прогресс в своём чате (glo-box.ru/orders)
6. Завершение — пока кнопок у посредника нет (проблема)

**Цепочка статусов:** `CREATED` → `ACCEPTED` → `COMPLETED` / `CANCELLED`

**Идентификатор:** `R-XXXX` (последние 4 символа UUID)

### Биржа заказов (MediatorOrder)
**Флоу:**
1. Покупатель создаёт заказ в общий пул
2. Посредник видит его в "Биржа" → нажимает "Взять заказ" (откликается)
3. Покупатель выбирает из откликнувшихся посредников
4. После выбора — заказ переходит в "Мои заказы" со статусом `ASSIGNED`
5. Посредник ведёт статус: Начать закупку → Передать клиенту
6. Покупатель подтверждает получение → `COMPLETED`

**Цепочка статусов:** `SEARCHING` → `SELECTING` → `ASSIGNED` → `AWAITING_PURCHASE_DATE` → `PURCHASING` → `DELIVERING` → `COMPLETED`

**Идентификатор:** `Z-XXXX`

## 8. API эндпоинты посредника (используются сейчас)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/mediator/me` | Профиль + данные |
| POST | `/mediator/ping` | Обновить статус онлайн |
| GET | `/mediator-orders/my` | Мои заказы (биржа) |
| GET | `/mediator-orders/mediator/available` | Доступные заказы из пула |
| POST | `/mediator-orders/:id/respond` | Откликнуться на заказ |
| POST | `/mediator-orders/:id/start-purchasing` | Начать закупку |
| POST | `/mediator-orders/:id/start-delivering` | Передать клиенту |
| GET | `/mediator-orders/:id/chats` | Чаты заказа |
| GET | `/mediator-orders/chats/:chatId/messages` | Сообщения биржевого чата |
| POST | `/mediator-orders/chats/:chatId/messages` | Отправить сообщение (биржа) |
| GET | `/order-requests/chats` | Список чатов прямых заявок |
| GET | `/order-requests/chats/:chatId/messages` | Сообщения прямого чата |
| POST | `/order-requests/chats/:chatId/messages` | Отправить сообщение (прямая) |
| GET | `/order-requests` | Мои прямые заявки |
| GET | `/order-requests/:id` | Детали прямой заявки |
| PATCH | `/order-requests/:id/items/:itemId/status` | Сменить статус товара |
| PATCH | `/mediator/settings` | Изменить ставку/мин. сумму |
| POST | `/mediator/change-password` | Сменить пароль |
| POST | `/mediator/change-email/request` + `/confirm` | Сменить email |
| POST | `/mediator/change-phone/request` + `/confirm` | Сменить телефон |

**Отсутствующие или нереализованные:**
- Нет `POST /order-requests/:id/complete` — нельзя завершить прямую заявку
- Нет `POST /order-requests/:id/cancel` — нельзя отменить прямую заявку (со стороны посредника)
- Нет `POST /mediator-orders/:id/complete` — завершение только через покупателя

## 9. Ключевые проблемы и пробелы

### Функциональные
1. **`/orders` — пустая страница.** URL существует, навигация не ведёт туда.
2. **Прямые заявки: нет смены статуса после принятия.** После `ACCEPTED` посредник не может ни завершить, ни отменить через интерфейс.
3. **Из чата нельзя управлять заказом.** Нужно уходить в Dashboard, открывать модалку.
4. **Из заказа нельзя перейти в чат.** Модалка Dashboard не имеет кнопки "Открыть чат".
5. **Медленная загрузка чатов.** Биржевые чаты грузятся N+1 запросом (1 заказ = 1 запрос за чатом).
6. **Нет счётчика непрочитанных** на иконке "Чаты" в навигации.
7. **Нет уведомлений в реальном времени** о новых сообщениях / новых заявках.

### UX/дизайн
8. **Dashboard и Чаты — два разных места** для одного и того же заказа. Посреднику приходится прыгать между страницами.
9. **Трекер товаров только в чате** (прямые заявки). Для биржевых заказов трекера нет.
10. **Быстрые ответы** — всего 6 шаблонов, нельзя добавить свои.
11. **История заказов** на дашборде есть, но без деталей чата.
12. **Нет информации о покупателе** в заказе (только имя).
