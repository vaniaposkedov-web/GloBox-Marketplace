1. ОБЩАЯ СТРУКТУРА САЙТА
════════════════════════════════════════════════════════════════════════════════

Сайт представляет собой мобильное веб-приложение (PWA), оптимизированное под
смартфоны. Разработан как SPA-подобное приложение — большинство переходов между
страницами происходит без перезагрузки.

Корневой layout (apps/mediator/src/app/layout.tsx):
  - Тема: светлая, белый фон (#ffffff), чёрный текст (#1a1a1a)
  - Шрифт: системный (ui-sans-serif, -apple-system, Segoe UI, Roboto)
  - Viewport: device-width, initialScale=1, maximumScale=1, userScalable=false
  - PWA manifest подключён (для добавления на рабочий стол)
  - -webkit-tap-highlight-color: transparent (нет синей вспышки при тапе)
  - overscroll-behavior: none (нет "резинового" отскока при скролле)

Маршруты приложения:
  /               → Лендинг (для неавторизованных) или редирект на /dashboard
  /login          → Страница входа
  /register       → Страница регистрации
  /dashboard      → Дашборд (главная для авторизованных)
  /orders         → Список заказов
  /orders/[id]    → Детальная страница конкретного заказа (чат + статусы)
  /chats          → Список чатов с покупателями
  /profile        → Профиль посредника
  /settings       → Настройки (ставка, минимальный заказ, безопасность)
  /settings/notifications → Настройки уведомлений
  /verify         → Мастер верификации (3 шага)
  /status         → Страница статуса заявки на верификацию
  /support        → Служба поддержки (чат с ботом / оператором)
  /finance        → Раздел финансов (если реализован)
  /privacy        → Политика конфиденциальности
  /terms          → Условия использования

3. НИЖНЯЯ НАВИГАЦИОННАЯ ПАНЕЛЬ (BottomNav)
════════════════════════════════════════════════════════════════════════════════

Компонент: apps/mediator/src/components/BottomNav.tsx
Расположение: фиксировано внизу (fixed bottom-0), z-index 50
Фон: bg-card/95 с backdrop-blur (полупрозрачная стекловидная плашка)
Отступ: safe-area-bottom (учитывает "подбородок" iPhone)

Состав (4 вкладки):

  ┌─────────────────────────────────────────────────────────┐
  │  🏠 Главная │ 📋 Заказы │ 💬 Чаты │ 👤 Профиль         │
  └─────────────────────────────────────────────────────────┘

  1. Главная   → /dashboard   — Иконка Home
  2. Заказы    → /orders      — Иконка ClipboardList  [badge: кол-во новых]
  3. Чаты      → /chats       — Иконка MessageSquare  [badge: непрочитанные]
  4. Профиль   → /profile     — Иконка User

BADGES (бейджи-счётчики):
  - Красный кружок с числом над иконкой
  - Для "Заказы": считаются новые заявки из /order-requests
  - Для "Чаты": считаются непрочитанные сообщения
  - Данные берутся из хука useNavBadges (локальное состояние + localStorage)
  - "Заказы" бейдж сбрасывается при переходе на /orders → вкладку "Новые"
  - "Чаты" бейдж сбрасывается при открытии страницы чатов

Активная вкладка:
  - Иконка: strokeWidth=2.5 + fill="currentColor" (заливка)
  - Текст: font-semibold
  - Цвет: text-primary (#1a1a1a)
  Неактивная: strokeWidth=1.8, font-normal, text-muted

Активность определяется по pathname (startsWith для вложенных маршрутов).

4. ДАШБОРД (/dashboard)
════════════════════════════════════════════════════════════════════════════════

Главная рабочая страница. Загружает данные из API каждые 15 секунд пока
посредник онлайн. Данные кэшируются между запросами.

──────────────────────────────────────────────────────────────────────────────
4.1. БАННЕР ВЕРИФИКАЦИИ (VerificationBanner)
──────────────────────────────────────────────────────────────────────────────
Всегда отображается вверху (до sticky-шапки).
Показывается только если профиль не APPROVED:
  - PENDING        → жёлтый баннер "Заявка на рассмотрении"
  - NEEDS_REVISION → оранжевый "Требуются правки — перейти в профиль →"
  - REJECTED       → красный "Заявка отклонена"
  - (null/NO)      → синий "Пройдите верификацию →"

──────────────────────────────────────────────────────────────────────────────
4.2. STICKY ШАПКА
──────────────────────────────────────────────────────────────────────────────
  Левая часть:
    - "Добро пожаловать" (xs, muted)
    - Имя посредника (lg, bold)
  Правая часть (только когда онлайн):
    - Зелёный пульсирующий индикатор + текст "В сети"

──────────────────────────────────────────────────────────────────────────────
4.3. ОФЛАЙН-СОСТОЯНИЕ (isOnline = false)
──────────────────────────────────────────────────────────────────────────────
Отображается когда посредник ещё не вышел на линию.

  [Иконка Power в большом квадрате]
  "Вы офлайн"
  "Потяните вправо, чтобы начать принимать заказы"

  Для одобренных аккаунтов (isApproved = true):
    [СЛАЙДЕР "Выйти на линию"]
      - Кастомный компонент SlideToggle
      - Большой трек с фиолетово-зелёным градиентом
      - Ползунок с иконкой Zap (молния)
      - Нужно потянуть ползунок вправо на 80% трека
      - При неполном свайпе — возвращается обратно (spring animation)
      - При достижении 80%+ → показывает "Отпустите ✓" → активация
      - После активации: ползунок → зелёный экран "Вы на линии!"
      - Значение сохраняется в localStorage ("mediator_online")

  Для неодобренных: серая плашка "Доступно после одобрения аккаунта"

──────────────────────────────────────────────────────────────────────────────
4.4. ОНЛАЙН-СОСТОЯНИЕ (isOnline = true, isApproved = true)
──────────────────────────────────────────────────────────────────────────────

[ИНДИКАТОР ОНЛАЙН — OnlineIndicator]
  Зелёная карточка (градиент f0fdf4 → dcfce7):

        * Красные = занятые слоты (лимит = 5 активных заказов)
        * Когда все заняты: "Лимит достигнут" красным цветом
    Справа:
      - Кнопка "Уйти" (WifiOff иконка) → переводит в офлайн

[CTA АКТИВНЫХ ЗАКАЗОВ — только если activeCount > 0]
  Фиолетовая карточка:
    - Иконка TrendingUp
    - "У вас N активных заказов"
    - "Перейти к работе"
    → Тап → /orders

[СЕКЦИЯ "НОВЫЕ ЗАЯВКИ"]
  Заголовок: Sparkles-иконка + "Новые заявки" + счётчик (фиолетовый бейдж)

    - Загрузка: 2 skeleton-плашки (animate-pulse)
    - Пусто: иконка Sparkles + "Новых прямых заявок пока нет"
    - Есть заявки: список карточек DirectRequestCard

    Левая граница: 4px, фиолетовый #7c3aed

    Правый блок:
      - Имя покупателя (сокращённое: "Иван И.") + бейдж "Новая"

[СЕКЦИЯ "БИРЖА ЗАКАЗОВ"]
  Заголовок: Globe-иконка + "Биржа заказов" + синий счётчик

    Красный баннер: "Завершите один из заказов, чтобы взять новый"

  КАРТОЧКА БИРЖЕВОГО ЗАКАЗА (AvailableCard):
    Левая граница: 4px, синий #4f46e5
    Если лимит → opacity 0.55 (визуально затемнена, тап всё равно работает)
    Левый блок: фото или синий квадрат с Globe
    Правый блок:
      - Имя покупателя + стрелка ChevronRight
      - Описание или ID заказа

    - Слоты заполнены: серая кнопка с замком (cursor-not-allowed)

──────────────────────────────────────────────────────────────────────────────
4.6. ЛОГИКА ПРИЁМА ЗАКАЗОВ
──────────────────────────────────────────────────────────────────────────────
Прямая заявка (direct):
  POST /order-requests/{id}/accept → редирект на /orders/{id}

Биржевая заявка (broadcast):
  POST /mediator-orders/{id}/respond → редирект на /orders/{id}

Обновление списка: автоматически каждые 15 секунд + ручная кнопка обновить.
Ping сервера: POST /mediator/ping каждые 10 минут (подтверждает онлайн-статус).

5. СТРАНИЦА ЗАКАЗОВ (/orders)
════════════════════════════════════════════════════════════════════════════════

Список всех заказов посредника. Обновляется каждые 12 секунд.
Если аккаунт не одобрен → показывает заглушку "Раздел недоступен".

──────────────────────────────────────────────────────────────────────────────
5.1. STICKY ШАПКА (с фильтрами)
──────────────────────────────────────────────────────────────────────────────
  Строка: "Рабочее пространство" / "Мои заказы" + кнопка обновить (RefreshCw)

  [СТРОКА ПОИСКА]
    Поле с иконкой поиска слева.
    Поиск по имени покупателя и ID заказа (zid).

  [ФИЛЬТР-ТАБЫ — сетка 3 колонки]
    Активный: синий фон #6366f1, белый текст, тень
    Неактивный: bg-card, border

    1. "Активные" (Package иконка) — статусы:
       ACCEPTED, SEARCHING, SELECTING, ASSIGNED,
       AWAITING_PURCHASE_DATE, PURCHASING, DELIVERING
    2. "Новые" (BellRing иконка) — статус CREATED
       При переходе — сбрасывает бейдж в навбаре
    3. "Архив" (Archive иконка) — статусы:
       COMPLETED, CANCELLED, NOT_FOUND, DISPUTE

    Каждый таб показывает число заказов в этой категории.

──────────────────────────────────────────────────────────────────────────────
5.2. КАРТОЧКА ЗАКАЗА (OrderCard)
──────────────────────────────────────────────────────────────────────────────
Цветная левая граница (4px):
  - Фиолетовая #6366f1 — активные и обычные
  - Оранжевая #f59e0b — требует внимания (замена товара)
  - Серая #e5e5e7 — завершённые

Структура карточки:

[ВЕРХНЯЯ СТРОКА]
  - Аватар покупателя (инициал на градиентном фоне)
  - Значок типа: Globe синий = биржевой, П фиолетовый = прямой
  - Имя покупателя + мигающий бейдж "Ждёт ответа" (если нужна замена)
  - Краткое описание статуса (getStatusDescription)
  - Время создания (справа) + ChevronRight

[ПОЛОСКА ИЗОБРАЖЕНИЙ] (если есть фото товаров)
  Первые 3 фото в ряд, если > 3 → "+N"

[ПРОГРЕСС-БАР] (только для прямых заявок с конкретными товарами)
  "Товары найдены: N / M"
  Заполненность полосы = найденные / всего
  Цвет: зелёный (все найдены) или фиолетовый градиент (в процессе)

[НИЖНЯЯ СТРОКА]
  - Цветная точка + статус (на языке из STATUS_CFG) + ID заказа (серый моно)
  - Сумма заказа (жирным)

Тап по карточке → /orders/{id} (детальная страница заказа)

──────────────────────────────────────────────────────────────────────────────
5.3. ДЕТАЛЬНАЯ СТРАНИЦА ЗАКАЗА (/orders/[id])
──────────────────────────────────────────────────────────────────────────────
Содержит:
  - Информацию о заказе (покупатель, товары, сумма, комиссия)
  - Чат с покупателем
  - Управление статусами товаров (найден / не найден / замена)
  - Кнопки для изменения статуса заказа

Статусы товаров (mediatorStatus):
  PENDING → FOUND → REPLACEMENT_REQUESTED → REPLACEMENT_APPROVED / NOT_FOUND

Статусы заказа (переходы инициирует посредник):
  ACCEPTED → SEARCHING → PURCHASING → DELIVERING → COMPLETED
  Любой → CANCELLED (с подтверждением)

6. СТРАНИЦА ЧАТОВ (/chats)
════════════════════════════════════════════════════════════════════════════════

Мессенджер для общения с покупателями в рамках конкретных заказов.

──────────────────────────────────────────────────────────────────────────────
6.1. СПИСОК ЧАТОВ (левая панель / полноэкранный список на мобиле)
──────────────────────────────────────────────────────────────────────────────
Sticky шапка: "Чаты" + иконка MessageCircle + кнопка обновить (RefreshCw)

Строка поиска: поиск по имени покупателя или ID заказа.

Каждый чат в списке:
  - Аватар покупателя (инициал на градиенте)
  - Имя покупателя + тип заказа (globe = биржа, иначе прямой)
  - ID заказа + статус (цветной текст из STATUS_CFG)
  - Последнее сообщение (truncate, 1 строка) + время

Порядок: по дате последнего сообщения (новые сверху).
При переходе в чат → сбрасывается бейдж "Чаты" в навбаре.

──────────────────────────────────────────────────────────────────────────────
6.2. ОТКРЫТЫЙ ЧАТ
──────────────────────────────────────────────────────────────────────────────
Sticky шапка чата:
  - Кнопка ArrowLeft (назад к списку)
  - Аватар + имя покупателя + статус заказа
  - Иконка предупреждения (AlertCircle) если нужна замена товара

Область сообщений (скроллируется, автоскролл к низу при новых сообщениях):
  Метки дат ("Сегодня", "Вчера", конкретная дата) — между группами сообщений

  СООБЩЕНИЯ:
    - "me" (посредник): выровнены по правому краю
      Фиолетово-синий градиент (#6366f1 → #8b5cf6), белый текст
      Двойная галочка (CheckCheck) в правом нижнем углу
    - "client" (покупатель): левый край
      bg-card, тёмный текст
      Аватар покупателя слева
    - "system": по центру, bg-blue-50, синий текст
      Префикс "🤖 GloBox Бот"
    - "danger": оранжевая рамка, предупреждающий фон

  Время сообщения: серый текст в правом нижнем углу

Поле ввода (sticky bottom):
  - Кнопка скрепки (Paperclip) — прикрепить файл/фото
  - Поле ввода "Написать сообщение..." (max 5000 символов)
  - Кнопка отправки (фиолетовая, иконка Send)
  - Enter без Shift → отправка; Shift+Enter → перенос строки

Прикрепление файлов:
  - Принимает: изображения jpeg/png/webp/heic, PDF, до 10 МБ
  - Превью выбранного файла отображается над полем ввода
  - Загружается через POST /mediator/upload
  - В сообщении отображается как ссылка с иконкой ExternalLink

Если заказ завершён (COMPLETED/CANCELLED): плашка "Заказ завершён" вместо ввода.

Обновление: каждые 5 секунд автоматически, без мигания (silent refresh).

14. КЛЮЧЕВЫЕ API ЭНДПОИНТЫ
════════════════════════════════════════════════════════════════════════════════

Базовый URL: https://glo-box.ru/api

Авторизация:
  POST /mediator/register             — регистрация
  POST /mediator/login                — вход
  GET  /mediator/me                   — профиль + статус

Онлайн/офлайн:
  POST /mediator/ping                 — подтвердить онлайн-статус

Заказы:
  GET  /order-requests                — прямые заявки (direct)
  POST /order-requests/:id/accept     — принять прямую заявку
  GET  /mediator-orders/mediator/available — биржа (broadcast)
  POST /mediator-orders/:id/respond   — откликнуться на биржевой заказ
  GET  /mediator-orders/mediator/my   — мои заказы из биржи

Чаты:
  GET  /mediator/chats                — список чатов
  GET  /mediator/chats/:id/messages   — сообщения чата
  POST /mediator/chats/:id/messages   — отправить сообщение

Профиль / настройки:
  PATCH /mediator/settings            — обновить ставку / минимум / аватар / пароль
  POST  /mediator/upload              — загрузить файл (base64)
  GET   /mediator/my-reviews          — количество отзывов
  GET   /mediator/leaderboard         — рейтинг посредников

Верификация:
  POST /mediator/submit               — подать заявку на верификацию

Уведомления:
  GET   /notifications/my             — список подписок
  PATCH /notifications/:channel       — изменить подписку

Поддержка:
  GET  /support/my-ticket             — текущий тикет поддержки
  POST /support/messages              — отправить сообщение в поддержку

15. ТЕХНИЧЕСКИЕ ДЕТАЛИ
════════════════════════════════════════════════════════════════════════════════

Аутентификация:
  JWT accessToken сохраняется в localStorage ("mediator.token").
  Передаётся в заголовке Authorization: Bearer <token>.
  При 401 ответе — редирект на /login.

Анимации (определены в globals.css):
  slideUp      — вход снизу вверх (форма входа, модалки)
  slideUpFast  — быстрый вход снизу
  scaleIn      — появление с масштабированием
  shake        — покачивание (ошибка в форме)
  fadeIn       — плавное появление
  pulse-glow   — пульсирующее свечение (онлайн-индикатор)
  spin-slow    — медленное вращение

CSS-классы scroll-reveal:
  .reveal      — элемент, который появляется при скролле
  .reveal.in-view — когда в viewport (добавляется через IntersectionObserver)
  .reveal-stagger — дочерние элементы появляются последовательно с задержкой
